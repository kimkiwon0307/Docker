## Chapter 2. 도커의 깊은 이해 (OS와 프로세스)

도커를 완벽하게 이해하기 위해서는 우리 컴퓨터의 근간이 되는 **운영체제(OS), 프로세스, 네임스페이스**의 개념을 먼저 파악해야 합니다.

### 1) 운영체제(OS)와 커널(Kernel)의 역할
* **운영체제(OS):** 컴퓨터의 하드웨어와 소프트웨어 전체를 총괄하는 **최고 관리자**입니다. (CPU, 메모리, 파일 시스템, 네트워크, 프로세스 관리)
* **커널(Kernel):** 운영체제의 가장 핵심적인 뇌이자 **엔진**입니다. CPU나 메모리 같은 물리적인 하드웨어를 직접 제어하고 관리합니다.
* **도커와의 관계:** 도커 컨테이너는 새로운 OS를 만드는 것이 아니라, **호스트 OS의 리눅스 커널을 공유**하여 사용합니다. 도커가 유독 리눅스 중심인 이유는 컨테이너 격리의 핵심 기술인 '네임스페이스'와 'cgroups'가 리눅스 커널의 고유 기능이기 때문입니다.

---

### 2) 프로그램, 프로세스, 스레드의 개념

도커의 관점에서 컨테이너는 결국 **"격리된 프로세스"**입니다. 이를 이해하기 위한 3가지 단계는 다음과 같습니다.

* **프로그램 (Program):** 실행되기 전의 정적인 파일 상태입니다. *(예: chrome.exe, nginx, python.py)*
* **프로세스 (Process):** 프로그램이 메모리에 실행되어 올라간 **'실행 중인 프로그램'** 상태입니다. 운영체제는 각 프로세스에 독립된 메모리, CPU 시간, 그리고 고유한 번호인 **PID(프로cess ID)**를 부여합니다.
* **스레드 (Thread):** 프로세스 내부에서 실제로 일을 하는 **작업의 단위**입니다. 프로세스가 '회사'라면 스레드는 일을 하는 '직원'에 비유할 수 있습니다.

> 💡 **도커의 핵심 관점**
> * **이미지:** 프로그램 (파일 상태)
> * **컨테이너:** 격리된 프로세스 (실행 환경을 갖춘 프로세스)
> * **컨테이너 종료:** 컨테이너 내부에서 실행되던 메인 프로세스가 종료되었음을 의미합니다.

---

### 3) 네임스페이스(Namespace) : 격리의 비밀
컨테이너들이 같은 OS 커널을 공유하면서도, 서로 완전히 독립된 컴퓨터처럼 보일 수 있는 이유는 리눅스 커널의 **네임스페이스(Namespace)** 기술 덕분입니다.

> 🏢 **네임스페이스 비유**
> 하나의 큰 건물(호스트 OS) 안에 **두꺼운 벽(Namespace)을 세워 방들을 분리**하는 것과 같습니다. 각 방에 있는 사람들은 벽에 가려져 오직 자기 방 내부만 볼 수 있으며, 서로 간섭할 수 없습니다.

#### 🛠️ 주요 네임스페이스 종류
* **PID Namespace:** 프로세스를 격리합니다. 각 컨테이너는 독립된 프로세스 번호(PID) 체계를 가집니다.
* **Network Namespace:** 네트워크를 격리합니다. 컨테이너마다 독립된 IP, 포트, 네트워크 인터페이스를 가질 수 있습니다.
* **Mount Namespace:** 파일 시스템을 격리합니다. 컨테이너마다 서로 전혀 다른 디렉터리 구조를 가진 것처럼 보이게 만듭니다.
* **UTS Namespace:** 호스트명(컴퓨터 이름)을 독립적으로 분리합니다.
* **IPC Namespace:** 프로세스 간의 통신(Inter-Process Communication) 통로를 격리합니다.

> 📌 **최종 요약**
> 컨테이너는 독립된 새로운 OS(가상 머신)가 아닙니다. 실제로는 **동일한 리눅스 커널을 공유하면서, 네임스페이스라는 가상의 벽을 통해 철저하게 격리되어 실행되는 '특수한 프로세스'**입니다.

## Chapter 3. 도커 기초 지식 및 핵심 가상화 개념

### 1) 도커(Docker)의 정의와 목표
* **도커란?** 운영체제나 가상머신이 아닌, 애플리케이션을 **컨테이너 형태로 패키징하고 실행하는 플랫폼**입니다.
* **핵심 기술:** 프로그램 실행에 필요한 소스 코드, 라이브러리, 실행 환경, 설정 파일까지 전부 하나로 묶어 어디서든 똑같이 실행되도록 만듭니다.
* **4대 핵심 목표:** `동일한 실행 환경` | `빠른 배포` | `높은 이식성` | `운영 자동화`

---

### 2) 컨테이너(Container)의 개념과 특징
* **정의:** 하나의 OS 안에서 철저하게 분리된 **'격리된 실행 공간'**입니다. 
* **특징:**
  * **격리성:** 파일 시스템, 네트워크, 프로세스가 완벽히 분리되어 안전합니다.
  * **경량성 & 신속성:** 가상 머신(VM)보다 용량이 매우 가볍고 부팅이 빠릅니다.
  * **이식성:** 로컬 환경, 테스트 서버, 클라우드 등 어디서나 동일하게 작동합니다.
* **독립 운영 체계 (MSA):** 하나의 서버 안에서 `Nginx`, `Node.js`, `MySQL`, `Redis` 등을 각각 독립된 컨테이너로 분리하여 운영합니다. 
  * *분리하는 이유:* 특정 서비스에 장애가 생겨도 다른 서비스에 영향을 주지 않으며(장애 격리), 개별 업데이트와 서비스 확장이 매우 쉽기 때문입니다.

---

### 3) 가상화 개념 비교: VM vs 컨테이너
> 💡 **가상화(Virtualization)란?** 하나의 물리 컴퓨터 자원을 쪼개어 여러 대의 컴퓨터처럼 사용하는 기술입니다. 과거 '서버 1대 = 서비스 1대' 구조의 심각한 자원 낭비를 해결하기 위해 등장했습니다.

* **💻 VM 가상화 (운영체제 가상화)**
  * *구조:* 하드웨어 ➡️ 하이퍼바이저 ➡️ **Guest OS** ➡️ 애플리케이션
  * *특징:* 각 VM마다 OS와 커널이 통째로 존재하여 무겁고 느립니다.
  * *🏢 비유:* 토지(하드웨어) 위에 **아파트(OS)를 여러 채 새로 건설**하는 것과 같습니다.

* **🐳 컨테이너 가상화 (프로세스 실행 환경 가상화)**
  * *구조:* 하드웨어 ➡️ Host OS 커널 ➡️ **컨테이너 런타임(도커)** ➡️ 컨테이너
  * *특징:* Host OS의 커널을 공유하므로 OS 부팅 과정이 없어 매우 가볍습니다.
  * *🏢 비유:* 이미 지어진 하나의 큰 건물 안에서 **벽을 세워 방(컨테이너)을 분리**하는 것과 같습니다.

---

### 4) 도커의 4대 구성 요소와 인프라 흐름

도커는 단일 프로그램이 아니라 아랫단계부터 유기적으로 연결된 컴포넌트의 조합입니다.

1. **Docker Client (클라이언트):** 사용자가 도커 명령어를 입력하는 창구(CLI 프로그램)입니다.
2. **Docker Engine (도커 엔진):** 클라이언트의 명령을 받아 이미지 관리, 컨테이너 생성, 네트워크 및 볼륨 관리를 수행하는 핵심 본체입니다.
3. **Image (이미지):** 애플리케이션과 환경을 압축해 놓은 실행 패키지이자 **설계도**입니다.
4. **Registry (레지스트리):** 빌드된 이미지들이 저장되고 공유되는 저장소입니다. *(예: Docker Hub, GitHub Packages(GHCR), AWS ECR)*

#### 🔄 도커 빌드 및 배포 흐름 (Workflow)
도커 기반의 인프라는 언제나 아래의 **5단계 파이프라인**으로 작동합니다.

```text
[1. Dockerfile 작성] ➡️ 코드와 환경 설정 정의
       ⬇️
[2. 이미지 빌드 (Build)] ➡️ Dockerfile을 실행 가능한 '이미지'로 압축
       ⬇️
[3. 저장소 푸시 (Push)] ➡️ 생성된 이미지를 원격 'Registry'에 업로드
       ⬇️
[4. 서버에서 풀 (Pull)] ➡️ 운영 서버나 쿠버네티스 클러스터에서 이미지 다운로드
       ⬇️
[5. 컨테이너 실행 (Run)] ➡️ 이미지를 격리된 '컨테이너(프로세스)'로 구동하여 서비스 개시

## Chapter 4. 우분투 환경에서 도커 설치

### 1) 사전 준비 사항
도커 설치를 진행하기 전, 터미널에서 아래의 3가지 필수 요건을 먼저 점검합니다.

1. **우분투 버전 확인**
   * 시스템 버전을 확인하여 도커 설치 가능 여부를 체크합니다.
   * ```bash
     cat /etc/os-release
     ```
2. **sudo 권한 확인**
   * 패키지 설치 및 시스템 설정을 위해 `root(루트)` 권한을 사용할 수 있는 계정인지 확인합니다.
3. **인터넷 연결 상태 점검**
   * 도커 패키지 및 관련 보안 인증서를 외부에서 다운로드해야 하므로 인터넷 연결이 필수적입니다.

3.2 도커 설치
  1. 패키지 업데이트 : sudo apt update
  2. 기존 도커 제거 : sudo apt remove docker docker-engine docker.io containerd runc : 버전이 오래된 경우를 위해 제거

 3. 필요한 패키지 설치 : sudo apt install -y ca-certificates curl gnupg : 도커 저장소 인증 준비
  4. docker GPG Key 등록 : sudo install -m 0755 -d /etc/apt/keyrings, curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg : 도커 공식 본사에서 발급한 정품 인증서를 우리 서버에 등록하는 과정
  5. docker Repository 등록 : echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null : 도커 공식 다운로드 서버 주소를 우리 서버의 등록하는 과정
  6. 패키지 목록 갱신 sudo apt update :목록 최신화
  7. Docker 설치 sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin : docker-ce(도커엔진), docker-ce-cli(도커 명령어도구), containerd(컨테이너 런타임), buildx(고급 빌드 기능), compose plugin(Docker Compose)
  8. 설치 확인 : docker version
