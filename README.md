## 🐧 2.1 사전 기초 지식
도커(Docker)는 완전히 새로운 기술이 아니라, 사실 **리눅스(Linux) 운영체제의 커널 기능 위에서 동작**합니다. 따라서 운영체제, 프로세스, 격리 기술의 개념을 먼저 이해해야 합니다.

### 💻 2.1.1 운영체제와 커널의 개념
* **운영체제 (OS, Operating System) :** 컴퓨터의 한정된 하드웨어 자원을 효율적으로 관리하고 사용자 및 프로그램에 분배하는 최고 관리자입니다.
* **커널 (Kernel) :** 운영체제의 핵심 엔진(뇌)으로, CPU, 메모리, 디스크 등의 하드웨어를 직접 제어하고 조율하는 역할을 합니다.
* **운영체제의 5대 핵심 역할 :**
  1. **프로세스 관리 :** 프로그램의 실행, 스케줄링, 종료 제어
  2. **메모리 관리 :** 프로그램(프로세스)마다 독립된 가상 메모리 공간 분리 및 할당
  3. **파일 시스템 관리 :** 디스크 내부의 파일 저장, 읽기, 권한 관리
  4. **네트워크 관리 :** 소켓 통신 및 인터넷 데이터 패킷 처리
  5. **사용자 관리 :** 다중 사용자 환경에서의 권한(Permission) 및 보안 통제
> 💡 **도커와 리눅스의 관계 :** 도커 컨테이너도 결국 운영체제가 실행하고 관리하는 **하나의 격리된 프로세스**일 뿐입니다. 도커가 리눅스 기반에서 태어난 이유는 도커를 지탱하는 핵심 격리 기술(`Namespace`, `cgroups`)이 리눅스 커널의 고유 기능이기 때문입니다.

### ⚙️ 2.1.2 프로그램, 프로세스, 스레드
* **프로그램 (Program) :** 디스크에 저장되어 있는 실행 전 상태의 정적 파일 (예: `nginx.exe`, 소스코드 빌드 파일)
* **프로세스 (Process) :** 프로그램이 메모리에 적재되어 **현재 실행 중인 상태**입니다. 운영체제는 프로세스마다 고유한 PID(프로세스 ID)를 부여하고, 전용 메모리 공간과 CPU 자원을 분배합니다. **(도커 컨테이너는 격리된 프로세스입니다)**
* **스레드 (Thread) :** 프로세스 내부에서 실제로 작업을 수행하는 **최소 실행 단위**입니다. 하나의 프로세스(회사) 안에 여러 스레드(직원)가 메모리를 공유하며 병렬 처리를 수행할니다.

### 🚧 2.1.3 네임스페이스(Namespace)와 자원 제한(cgroups)
컨테이너가 마치 독립된 하나의 가상 서버처럼 작동할 수 있는 비밀은 리눅스 커널의 두 가지 기술 덕분입니다.

1. **네임스페이스 (Namespace) :** 특정 프로세스에게 물리 호스트의 자원을 다 보여주지 않고, **"너만의 가상 세계"를 만들어 시야를 격리하는 기술**입니다.
   * **PID Namespace :** 프로세스 트리를 격리합니다. 컨테이너 내부의 메인 프로세스는 스스로 PID 1번으로 인식합니다.
   * **Network Namespace :** 네트워크 스택을 격리하여 컨테이너마다 고유한 독립 가상 IP, 포트 번호, 라우팅 테이블을 가집니다.
   * **Mount (mnt) Namespace :** 파일 시스템 마운트 지점을 격리하여 컨테이너가 호스트와 다른 독자적인 디렉토리 구조를 보게 합니다.
   * **UTS Namespace :** 독립적인 호스트 이름(Hostname)과 도메인 이름을 부여합니다.
   * **IPC Namespace :** 프로세스 간 통신(Shared Memory 등) 통로를 컨테이너 별로 분리합니다.
2. **cgroups (Control Groups - 내용 보완) :** 네임스페이스가 시야를 격리한다면, cgroups는 자원의 양을 통제합니다. 특정 컨테이너가 호스트의 CPU나 메모리를 과도하게 점유하여 다른 서비스에 피해를 주지 않도록 **자원의 최대 사용 한도(CPU 코어 수 제한, 메모리 1GB 제한 등)를 강제하는 기술**입니다.

### 🐳 2.2.4 도커 기초 지식

### 📦 2.2.1 도커(Docker)의 정의와 목표
* **정의 :** 애플리케이션과 이를 실행하는 데 필요한 모든 환경(라이브러리, 의존성 파일, 설정 값 등)을 **컨테이너라는 표준화된 형태로 패키징하고 배포·실행하는 오프소스 플랫폼**입니다.
* **핵심 목표 :** 어디서나 동일한 실행 환경 보장(이식성), 가볍고 빠른 배포, 인프라 운영 자동화 극대화.

### 🛡️ 2.2.2 컨테이너(Container)의 핵심 특징
* **격리성 :** 하나의 물리 서버 안에서 여러 개의 컨테이너(Nginx, MySQL, Redis 등)가 서로의 파일이나 네트워크를 전혀 침범하지 않고 독립 실행됩니다.
* **경량성 :** 호스트의 커널을 그대로 공유하기 때문에 구조적으로 무겁지 않습니다.
* **빠른 속도 :** OS 부팅 과정이 필요 없으므로, 프로세스가 켜지는 속도(수밀리초)와 동일하게 즉시 실행됩니다.
* **이식성 :** "내 컴퓨터에서는 잘 되는데 서버에선 왜 안 되지?"라는 고질적인 환경 문제를 완벽히 해결합니다. 도커만 깔려 있다면 로컬, 스테이징, 운영 클라우드 환경 어디서든 100% 동일하게 작동합니다.

### ⚖️ 2.2.3 가상화 모델 비교 (VM vs 컨테이너)
하나의 물리 서버를 쪼개어 가상 공간을 만든다는 목적은 같지만 가상화의 깊이가 다릅니다.



#### 1) 하이퍼바이저 가상화 (VM)
* **구조 :** `물리 하드웨어` $\rightarrow$ `하이퍼바이저(Hypervisor)` $\rightarrow$ **`Guest OS (가상 운영체제)`** $\rightarrow$ `애플리케이션(App)`
* **특징 :** 하드웨어 자체를 가상화합니다. 가상머신마다 독립된 OS(kernel 포함)를 통째로 부팅시켜야 하므로 기가바이트(GB) 단위로 무겁고, 부팅 속도가 수 분 걸리며 CPU/메모리 오버헤드가 큽니다.

#### 2) 컨테이너 가상화 (Docker)
* **구조 :** `물리 하드웨어` $\rightarrow$ `Host OS` $\rightarrow$ `도커 엔진(Docker Engine)` $\rightarrow$ **`컨테이너 (커널 공유)`**
* **특징 :** OS 레벨 가상화입니다. 호스트 리눅스의 커널 엔진을 모든 컨테이너가 완벽히 공유하고, 네임스페이스로 격리만 해두었기 때문에 메가바이트(MB) 단위로 매우 가볍고 시작과 종료가 즉시 이루어집니다.

### 🛠️ 2.2.4 도커 핵심 구성 요소와 실무 워크플로우

### 1️⃣ 도커 클라이언트 (Docker Client)
* 사용자가 터미널 창에 `docker run`, `docker build`와 같은 도커 명령어를 입력하는 인터페이스 창구입니다. 이 명령은 도커 데몬(엔진)에 API 형태로 전달됩니다.

### 2️⃣ 도커 엔진 / 데몬 (Docker Engine / Daemon - `dockerd`)
* 백그라운드에서 상시 작동하며 실제 무거운 일을 도맡아 하는 핵심 엔진입니다. 이미지 관리, 컨테이너 생성 및 실행 제어, 네트워크 장치 연결, 스토리지 볼륨 관리 등을 책임집니다.

### 3️⃣ 도커 이미지 (Docker Image)
* 컨테이너를 실행하기 위해 필요한 모든 파일과 설정, 라이브러리를 압축해 놓은 **정적 읽기 전용(Read-Only) 템플릿**입니다. (클래스와 객체 관계에서 '클래스'에 비유)

### 4️⃣ 도커 컨테이너 (Docker Container)
* 도커 이미지를 기반으로 메모리에 올려 **실제 살아 움직이게 만든 실행 상태(Instance)**입니다. 컨테이너가 구동되면 이미지 레이어 위에 독립된 읽기/쓰기(Read-Write) 레이어가 한 층 더해져 데이터를 변경하거나 저장할 수 있게 됩니다.

### 5️⃣ 도커 레지스트리 (Docker Registry)
* 빌드가 완료된 도커 이미지들을 중앙에서 업로드하고 다운로드할 수 있는 **이미지 저장소 라이브러리**입니다. 전 세계 표준 공용 저장소인 **도커 허브(Docker Hub)**가 대표적이며, 기업 내부용 사설 레지스트리(AWS ECR 등)를 구축하기도 합니다.

## 3장 도커 설치 및 첫 실습

### 📋 3.1 사전 준비 사항
도커를 안전하게 설치하고 운용하기 위해, 본격적인 설치 전 아래 6가지 요구사항을 체크합니다.

1. **Ubuntu 버전 확인 :** 도커는 최신 리눅스 커널 환경에서 가장 안정적입니다. (우분투 LTS 버전 권장)
   * 확인 명령어: cat /etc/os-release

2. **sudo 권한 확인 :** 패키지 제어 및 가상 네트워크 장치 생성을 위해 관리자(root) 권한이 반드시 필요합니다.
   * 확인 명령어: sudo whoami (결과가 root로 나와야 합니다.)

3. **인터넷 연결 상태 :** Docker 공식 APT 저장소로부터 대용량 패키지를 다운로드해야 하므로 외부 인터넷망 연결이 필수적입니다.

4. **디스크 여유 공간 :** 도커 이미지, 컨테이너 레이어, 볼륨 데이터가 지속적으로 쌓이므로 루트 패치에 최소 수 GB 이상의 디스크 용량을 확보해야 합니다.

5. **메모리 제원 :** 다중 컨테이너 및 고부하 애플리케이션(DB, 웹 서버 등)의 원활한 병렬 구동을 위해 최소 **8GB 이상**의 RAM 시스템 환경을 권장합니다.

6. **CPU 가상화 활성화 :** 호스트 운영체제(OS) 수준에서 컨테이너 프로세스를 효율적으로 격리·구동할 수 있도록 CPU 가상화 기능(Intel VT-x / AMD-V)이 켜져 있어야 합니다.

### 🛠️ 3.2 도커 설치
리눅스는 가상 OS를 거치지 않고 Docker가 호스트 커널을 직접 사용할 수 있으므로, Ubuntu 환경에서는 가벼운 'Docker Engine'만 설치하여 사용하는 것이 일반적입니다.

1. **패키지 목록 업데이트 :** sudo apt update
2. **기존 구버전 Docker 제거 :** sudo apt remove docker docker-engine docker.io containerd runc
   * 구버전 패키지가 남아있으면 설치 충돌이 발생할 수 있으므로 사전에 정리합니다.
3. **필수 패키지 설치 :** sudo apt install -y ca-certificates curl gnupg
   * Docker 저장소의 보안 인증 및 암호화 키를 다루기 위한 필수 도구입니다.
4. **Docker GPG Key 등록 :** * sudo install -m 0755 -d /etc/apt/keyrings
   * curl -fsSL [https://download.docker.com/linux/ubuntu/gpg](https://download.docker.com/linux/ubuntu/gpg) | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
   * sudo chmod a+r /etc/apt/keyrings/docker.gpg
   * 💡 GPG Key란? 패키지 위변조를 방지하기 위해 진짜 Docker 공식 저장소에서 제공하는 안전한 패키지가 맞는지 검증하는 인증서입니다.
5. **Docker Repository 등록 :** * echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] [https://download.docker.com/linux/ubuntu](https://download.docker.com/linux/ubuntu) $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
   * 💡 Repository 등록이란? Ubuntu 시스템의 패키지 매니저(apt)에게 "앞으로 소프트웨어를 다운로드할 때 Docker 공식 저장소 경로도 함께 조회해라"라고 등록해 주는 과정입니다.
6. **패키지 목록 갱신 :** sudo apt update
   * 새로 등록한 Docker 저장소의 최신 패키지 정보를 시스템에 반영합니다.
7. **Docker 엔진종류 최종 설치 :** sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

📑 설치되는 핵심 구성 요소 역할:
* **docker-ce :** 도커 엔진 (실제 컨테이너를 구동하고 백그라운드에서 관리하는 핵심 데몬)
* **docker-ce-cli :** 도커 명령어 도구 (사용자가 터미널 창에 명령어를 입력할 수 있게 해주는 인터페이스)
* **containerd.io :** 컨테이너 런타임 (리눅스 커널 기능을 직접 활용해 프로세스를 격리하는 실구동부)
* **buildx-plugin :** 고급 빌드 기능 (다양한 CPU 아키텍처 환경에 맞춰 이미지를 빌드하는 확장 도구)
* **compose-plugin :** Docker Compose 기능 (여러 개의 컨테이너 환경을 하나의 파일로 묶어 일괄 제어)

8. **설치 상태 최종 확인 :** docker version
   * 🚨 permission denied 에러 발생 시 해결법: Docker 데몬은 기본적으로 관리자(root) 권한으로 구동되므로 일반 계정에서는 소켓 접근 권한이 거부됩니다. 현재 사용자를 docker 그룹에 영구 추가하여 해결합니다.
   * 해결 방법: sudo usermod -aG docker $USER 입력 후, 'newgrp docker'를 입력하거나 세션을 재접속합니다.
   * 최종 검증: 'docker ps'로 정상 작동을 확인하고, 'systemctl status docker'로 서비스 구동 상태를 체크합니다.

### 🚀 3.3 Hello-World 및 Nginx 첫 실습
도커가 정상적으로 설치되었다면 기본 이미지들을 활용해 컨테이너의 핵심 작동 원리를 파악합니다.

#### 🧪 3.3.1 hello-world 실행 시 내부 작동 메커니즘
* 실행 명령어: docker run hello-world

도커는 철저히 이미지 기반으로 동작하며, run 명령 한 번에 pull(다운로드), create(생성), start(실행) 과정이 모두 포함되어 있습니다. 내부적으로는 아래 7단계의 순서대로 일어납니다.
1. **로컬 창고 수색 :** 내 컴퓨터(로컬) 환경에 hello-world 이미지가 이미 다운로드되어 있는지 확인합니다.
2. **원격 저장소 접속 :** 로컬에 파일이 없다면 인터넷망을 통해 글로벌 공용 저장소인 도커 허브(Docker Hub)에 접속합니다.
3. **이미지 다운로드 (Pull) :** 도커 허브로부터 최신 hello-world 이미지를 안전하게 다운로드합니다.
4. **컨테이너 공간 생성 (Create) :** 다운로드한 정적 이미지를 바탕으로 독립된 격리 샌드박스 공간을 개설합니다.
5. **프로세스 실행 (Start) :** 컨테이너 내부의 메인 애플리케이션 프로세스를 가동합니다.
6. **메시지 출력 :** 화면에 환영 문구(Hello from Docker!)를 출력합니다.
7. **프로세스 및 컨테이너 종료 :** 텍스트 출력이 완료되어 내부 메인 프로세스가 끝나면, 컨테이너도 자원을 반납하며 그 즉시 자동 종료(Exited) 상태로 전환됩니다.

📌 컨테이너 생명주기 확인 가이드:
* 컨테이너는 내부에 켜진 메인 프로세스가 죽으면 가동을 멈춥니다.
* 현재 실행 중인 실시간 컨테이너 확인: docker ps
* 가동이 끝나고 종료된 컨테이너까지 전체 내역 확인: docker ps -a

#### 🌐 3.3.2 nginx 웹 서버 실시간 백그라운드 가동 실습
웹 서버처럼 종료되지 않고 상시 켜져서 외부 트래픽을 대기해야 하는 서비스는 아래 옵션을 조합하여 실행합니다.

* 실행 명령어: docker run -d -p 80:80 --name my-web nginx

💡 핵심 실행 옵션 상세 분석:
* **-d (Detached 모드) :** 컨테이너를 백그라운드(화면 뒤편)에서 조용히 실행하도록 만듭니다. 이 옵션이 있어야 웹 서버가 켜진 상태에서도 터미널 창이 먹통이 되지 않고 다음 명령어를 연속해서 입력할 수 있습니다.
* **-p 80:80 (포트 포워딩) :** 외부 호스트의 포트와 컨테이너 내부의 전용 포트를 1:1로 단단히 연결합니다. 외부 사용자가 내 서버 IP의 80번 포트로 접속하면, 도커 엔진이 컨테이너 내부 샌드박스의 80번 포트로 트래픽을 안전하게 중계(릴레이)해 줍니다.
* **nginx :** 웹 서버 구동을 위해 도커 허브로부터 불러올 표준 웹 서버 베이스 이미지 명칭입니다.

## 🐳 4장. 도커 기초
> **Docker**는 이미지를 이용해 컨테이너를 실행하는 기술입니다.

---

### 4.1 도커 기초 개념

#### 4.1.1 도커 동작 방식
1. **사용자**: 터미널을 통해 명령어를 입력합니다.
2. **Docker Client**: 사용자가 입력한 명령어(ex. `docker run`, `docker ps`, `docker images`)를 받아 Docker Engine에 전달합니다.
3. **Docker Engine**: 도커의 실제 핵심 엔진입니다. 명령을 받아 이미지 관리, 컨테이너 생성, 네트워크 및 볼륨 생성 등의 실질적인 작업을 수행합니다.
4. **이미지 확인**: 실행하려는 이미지가 로컬에 있는지 확인합니다.
5. **컨테이너 생성**: 이미지를 기반으로 독립된 컨테이너 공간을 만듭니다.
6. **프로세스 실행**: 컨테이너 내부에서 애플리케이션 프로세스를 구동합니다.

---

#### 4.1.2 도커 이미지 (Docker Image)
> 💡 **이미지란?** 도커에서 가장 중요한 개념으로, 컨테이너의 **'설계도'**라고 부릅니다.
> * **비유:** 도커 이미지(`붕어빵 틀`) ◀─▶ 도커 컨테이너(`붕어빵`)
> * *ex) nginx 이미지 안에는 nginx 프로그램, 필요한 라이브러리, 설정 파일이 모두 포함되어 있습니다.*

* **📌 이미지의 주요 특징**
    1. **읽기 전용 (Read-Only):** 이미지는 한 번 생성되면 수정되지 않습니다.
    2. **다중 컨테이너 생성 가능:** 하나의 동일한 이미지로 여러 개의 독립된 컨테이너를 동시에 생성할 수 있습니다.

---

#### 4.1.3 도커 컨테이너 (Docker Container)
> 💡 **컨테이너란?** 이미지를 실행한 **'결과물'**입니다.
> `docker run nginx`를 실행하면 [ nginx 이미지 ] ──> [ 컨테이너 생성 ] ──> [ nginx 프로세스 실행 ] 단계를 거칩니다.

* **💻 가상머신(VM) vs 컨테이너**
    * **VM:** 각 가상머신마다 독립된 OS(Guest OS)를 통째로 포함하여 무겁습니다.
    * **Container:** Host 리눅스 커널을 공유하며, VM이 아니라 호스트 OS단에서 **격리된 프로세스**로 동작합니다.
    * *따라서 Ubuntu 서버에서 `docker run nginx`를 실행하는 것은 실제 Linux 내부에서 격리된 nginx 프로세스를 실행하는 것과 같습니다.*

* **📌 컨테이너의 주요 특징**
    1. **독립성:** 각 컨테이너는 자신만의 독립된 파일 시스템을 사용합니다.
    2. **격리성:** 프로세스 단위로 철저히 분리되어 서로 영향을 주지 않습니다.
    3. **이식성:** 환경에 구애받지 않고 어디서나 동일하게 실행됩니다.
    4. **빠른 시작:** OS 부팅 과정이 없으므로 수 초 이내에 가동됩니다.

---

#### 4.1.4 Hello-World 실행 과정 상세
`docker run hello-world` 명령어가 처리되는 전체 생명주기(Lifecycle)는 다음과 같습니다.

1. **사용자 입력:** `docker run hello-world` 실행
2. **Docker Engine 확인:** 로컬에 `hello-world` 이미지가 있는지 검사
3. **Docker Hub 접속:** 로컬에 이미지가 없다면 인터넷을 통해 도커 공식 이미지 저장소(Docker Hub)에 접속
4. **이미지 다운로드:** 저장소로부터 `hello-world` 이미지 다운로드 (`image pull`)
5. **컨테이너 생성:** 다운로드한 이미지를 기반으로 컨테이너 공간 개설 (`image -> container`)
6. **프로세스 실행:** 컨테이너 내부에서 `hello-world` 프로그램 가동
7. **메시지 출력:** 화면에 `Hello from Docker!` 환영 문구 출력
8. **프로세스 종료:** 프로그램 실행 및 출력 작업 완료
9. **컨테이너 종료:** 메인 프로세스가 종료됨에 따라 컨테이너도 즉시 자동 종료

### 4.2 도커 기초 명령어

#### 4.2.1 도커 이미지 다운로드
> 💡 **이미지(Image)란?** 컨테이너를 생성하기 위한 **'독립된 설계도'**입니다.

* **명령어:** `docker pull nginx`
* **확인 명령어:** `docker images`

  4.2.2 도커 이미지 상세 구조
    nginx 이미지는 무엇으로 구성될까? : 실제로는 Linux OS 일부 + nginx 프로그램 + 라이브러리 + 설정 파일이다.
    이미지 레어 구조
      Docker 이미지 특징

    왜 중요할까? 이미지를 재사용 가능하다. Ubuntu 기반 이비지 100개이면 Ubuntu 부분은 공유해서 용량을 절약한다.

  4.2.3 도커 이미지 목록 확인
    명령어 : docker images, docker image ls : 현재 PC에 저장된 이미지 목록

  4.2.4 도커 컨테이너 실행
    기본 실행 : docker run nginx
    실행 순서 : 이미지 확인 -> 컨테이너 생성 -> nginx 실행
    백그라운드 실행 : docker run -d nginx : -d는 detached mode 
    포트 연결 : docker run -d -p 80:80 nginx : 호스트 80 <-> 컨테이너 80 
    이름 지정 : docker run -d --name my-nginx nginx 

  4.2.5 도커 컨테이너 목록 확인
    실행 중인 컨테이너 : docker ps
    종료 포함 전체 보기 : docker ps -a

  4.2.6 컨테이너 내부 접속
    docker exec -it my-nginx bash : exec 의미는 컨테이너 내부 명령 실행
    파일 확인 : ls
    프로세스 확인 : ps -ef
    종료 : exit
    bash 없을 경우 : docker exec -it 컨테이너명 sh

  4.2.7 컨테이너 삭제
    중지 : docker stop my-nginx
    삭제 : docker rm my-nginx
    한번에 : docker rm -f my-nginx

  4.2.8 이미지 삭제
    목록 확인 : docker images
    삭제 : docker rmi nginx 또는 docker images rm nginx : 컨테이너가 사용중이면 삭제 불가

  4.2.9 도커 이미지 변경
    태그 변경 : docker tag nginx my-nginx:v1 : 같은 이미지 다른 이름, 실무에서 버전관리 하려고 이용함

  4.2.10 도커 이미지 명령어 모음
    다운로드 : docker pull nginx
    목록 : docker images
    상세구조 : docker history nginx
    태그변경 : docker tag nginx my-nginx:v1
    삭제 : docker rmi nginx

  4.2.11 도커 컨테이너 명령어 모음
    실행 : docker run nginx
    백그라운드 실행 : docker run -d nginx
    실행 목록 : docker ps
    전체 목록 : docker ps -a
    내부 접속 : docker exec -it 컨테이너명 bash
    로그 확인 : docker logs 컨테이너명
    중지 : docker stop 컨테이너명
    삭제 : docker rm 컨테이너명
