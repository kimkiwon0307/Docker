## 1. 가상 머신(Virtual Machine)이란?

가상 머신(VM)은 하나의 물리 서버에서 여러 개의 독립적인 가상 컴퓨터를 실행하는 기술이다.

하이퍼바이저(Hypervisor)를 통해 CPU, 메모리, 디스크 등의 하드웨어 자원을 가상화하고, 각 VM에 별도의 게스트 운영체제를 설치하여 실행한다.

### 가상 머신의 특징

- 각 VM은 독립적인 게스트 운영체제와 커널을 실행한다.
- 하나의 물리 서버에서 여러 운영체제를 실행할 수 있다.
- VM마다 CPU, 메모리, 디스크 등의 자원을 할당할 수 있다.
- 서로 다른 운영체제를 실행할 수 있다.
- 게스트 OS를 별도로 설치하고 관리해야 한다.

### 장점
- 운영체제 단위의 독립적인 실행 환경 제공
- 서로 다른 운영체제 사용 가능
- 강한 격리 경계 제공
- 서버별 독립적인 관리 가능

### 단점
- 각 VM에서 게스트 OS를 실행하므로 자원 사용량 증가
- 운영체제 부팅에 시간 소요
- 각 VM의 운영체제 업데이트 및 관리 필요

---

## 2. 도커 컨테이너(Docker Container)란?

컨테이너는 애플리케이션과 실행에 필요한 라이브러리 및 파일을 묶어 격리된 환경에서 실행하는 기술이다.

Docker는 컨테이너를 쉽게 생성, 실행, 관리할 수 있도록 지원하는 플랫폼이다.

### 컨테이너의 특징

- 호스트 Linux 운영체제의 커널을 공유한다.
- 컨테이너마다 별도의 게스트 OS를 부팅하지 않는다.
- 컨테이너마다 애플리케이션과 필요한 라이브러리를 포함할 수 있다.
- 하나의 서버에서 여러 컨테이너를 실행할 수 있다.
- 일반적으로 VM보다 빠르게 시작하고 자원 사용이 효율적이다.

### 장점
- 빠른 실행 및 배포
- 상대적으로 적은 자원 사용
- 애플리케이션별 격리 환경 제공
- 동일한 이미지 기반으로 여러 컨테이너 실행 가능
- 개발 및 운영 환경 구성의 일관성 향상

### 단점
- 호스트 커널을 공유하므로 VM과 격리 특성이 다르다.
- 커널 취약점의 영향을 받을 가능성이 있다.
- 네트워크, 볼륨, 로그 등의 운영 관리가 필요하다.

---

## 3. 가상 머신과 Docker 컨테이너 비교

| 구분 | 가상 머신(VM) | Docker 컨테이너 |
|---|---|---|
| 가상화 방식 | 하드웨어 수준 가상화 | OS 수준 가상화 |
| 운영체제 | VM마다 게스트 OS 실행 | 호스트 커널 공유 |
| 커널 | VM마다 독립적 | 호스트 커널 공유 |
| 실행 속도 | 상대적으로 느림 | 일반적으로 빠름 |
| 자원 사용 | 게스트 OS 자원 필요 | 게스트 OS 중복 실행 불필요 |
| 격리 | 가상 하드웨어 및 독립 커널 | Namespace 등의 커널 격리 기능 |
| 운영체제 선택 | 서로 다른 커널 실행 가능 | 호스트 커널과 호환 필요 |
| 대표 기술 | VMware, KVM | Docker, Podman |

### 핵심 차이

**VM은 각 가상 머신이 독립적인 게스트 OS와 커널을 실행하지만, Docker 컨테이너는 호스트 Linux 커널을 공유한다.**

따라서 컨테이너는 별도의 게스트 OS를 부팅하지 않아도 되므로 일반적으로 VM보다 가볍고 빠르게 실행된다.

※ Docker 컨테이너 역시 CPU, 메모리 등의 자원을 사용하며, 항상 VM보다 성능이 좋은 것은 아니다.

---

## 4. Docker 컨테이너의 격리 원리

Docker 컨테이너는 Linux 커널의 Namespace와 cgroups 등의 기능을 이용하여 프로세스를 격리하고 자원 사용을 관리한다.

### 4.1 Namespace

Namespace는 프로세스가 볼 수 있는 시스템 자원을 격리하는 Linux 커널 기능이다.

대표적인 Namespace는 다음과 같다.

| 종류 | 역할 |
|---|---|
| PID Namespace | 프로세스 ID 공간 격리 |
| Network Namespace | 네트워크 인터페이스, IP, 라우팅 등의 공간 격리 |
| Mount Namespace | 파일시스템 마운트 공간 격리 |
| UTS Namespace | 호스트 이름 및 도메인 이름 격리 |

예를 들어 Nginx 컨테이너 내부에서 프로세스를 조회하면 기본적으로 해당 PID Namespace에 속한 프로세스를 확인하게 된다.

### 4.2 cgroups (Control Groups)

cgroups는 프로세스 그룹의 CPU, 메모리 등 자원 사용을 관리하고 제한하는 Linux 커널 기능이다.

예시:

- Nginx 컨테이너: 메모리 512MB 제한
- Spring Boot 컨테이너: 메모리 2GB 제한
- MySQL 컨테이너: 메모리 1GB 제한

위 수치는 예시이며 실제 운영 환경에서는 서비스 특성에 따라 결정한다.

### Namespace와 cgroups 차이

- **Namespace:** 프로세스가 볼 수 있는 자원을 격리한다.
- **cgroups:** 프로세스가 사용할 수 있는 자원을 관리하고 제한한다.

두 기술은 역할이 다르며, 컨테이너의 격리와 자원 관리를 구현하기 위해 함께 사용된다.

## 5. Docker 이미지와 컨테이너

### Docker 이미지(Image)

Docker 이미지는 애플리케이션 실행에 필요한 파일, 라이브러리 및 설정 정보를 포함하는 템플릿이다.

특징:
- 컨테이너 생성의 기반이 된다.
- 동일한 이미지로 여러 컨테이너를 생성할 수 있다.
- 이미지 자체는 실행 중인 프로세스가 아니다.

### Docker 컨테이너(Container)

Docker 컨테이너는 이미지를 기반으로 생성한 실행 인스턴스이다.

특징:
- 이미지를 기반으로 생성된다.
- 독립된 프로세스 환경에서 실행된다.
- 하나의 이미지로 여러 컨테이너를 생성할 수 있다.

### 예시

```text
Nginx 이미지
    |
    |-- Nginx 컨테이너 1
    |
    |-- Nginx 컨테이너 2
    |
    |-- Nginx 컨테이너 3
```

**이미지는 컨테이너를 생성하기 위한 템플릿이며, 컨테이너는 이미지를 기반으로 생성된 인스턴스이다.**


현재 운영체제에서 실행 중인 프로세스 목록을 확인한다.

추후 Docker 컨테이너 내부에서 동일한 명령어를 실행하여 프로세스 격리 차이를 비교한다.

## 7. 실무 적용 예시

### 상황

Nginx 웹 서버 3개를 운영해야 한다.

### VM 방식

1. VMware에서 Ubuntu VM 3대를 생성한다.
2. 각 VM에 Ubuntu를 설치한다.
3. 각 VM에 Nginx를 설치한다.
4. 각각의 Nginx 서비스를 실행하고 관리한다.

### Docker 방식

1. Ubuntu 서버 1대를 준비한다.
2. Docker Engine을 설치한다.
3. Nginx 이미지를 준비한다.
4. Nginx 컨테이너 3개를 생성하고 실행한다.

### 차이점

VM 방식은 각 서버가 독립적인 운영체제와 커널을 실행한다.

Docker 방식은 하나의 Linux 커널을 공유하면서 Nginx 컨테이너 3개를 격리하여 실행할 수 있다.

따라서 Docker 방식은 게스트 OS를 중복 실행할 필요가 없어 자원 사용을 줄일 수 있다.

단, 실제 운영에서는 장애 격리와 가용성 요구사항에 따라 여러 VM이나 물리 서버에 컨테이너를 분산할 수도 있다.

## 8. 면접 질문

### Q1. VM과 Docker 컨테이너의 차이는 무엇인가요?

VM은 하이퍼바이저를 이용해 가상 하드웨어를 제공하고, 각 VM에서 독립적인 게스트 OS와 커널을 실행합니다.

반면 Docker 컨테이너는 호스트 Linux 커널을 공유하면서 Namespace와 cgroups 등을 이용해 애플리케이션을 격리하고 자원을 관리합니다.

따라서 컨테이너는 별도의 게스트 OS를 부팅하지 않아도 되므로 일반적으로 시작 속도가 빠르고 자원 사용이 효율적입니다.

### Q2. Docker 컨테이너가 VM보다 상대적으로 가벼운 이유는 무엇인가요?

컨테이너마다 별도의 게스트 운영체제와 커널을 실행하지 않고 호스트 커널을 공유하기 때문입니다.

### Q3. Namespace와 cgroups의 차이는 무엇인가요?

Namespace는 프로세스가 볼 수 있는 시스템 자원을 격리하는 기능이고, cgroups는 CPU와 메모리 등의 자원 사용을 관리하고 제한하는 기능입니다.

### Q4. Docker 이미지와 컨테이너의 차이는 무엇인가요?

이미지는 애플리케이션 실행에 필요한 파일과 설정을 담은 템플릿이고, 컨테이너는 해당 이미지를 기반으로 생성한 실행 인스턴스입니다.

## 9. 1교시 핵심 요약

1. VM은 각 가상 머신마다 독립적인 게스트 OS와 커널을 실행한다.
2. Docker 컨테이너는 호스트 Linux 커널을 공유한다.
3. 컨테이너는 별도 게스트 OS 부팅이 필요 없어 일반적으로 시작 속도가 빠르고 자원 사용이 효율적이다.
4. Namespace는 프로세스의 실행 환경을 격리한다.
5. cgroups는 CPU, 메모리 등의 자원 사용을 관리하고 제한한다.
6. Docker 이미지는 실행 템플릿이고 컨테이너는 이미지를 기반으로 생성한 인스턴스이다.
7. VM과 컨테이너는 서로 배타적인 기술이 아니며 함께 사용할 수 있다.

## 1. Docker를 사용하는 이유

Docker는 애플리케이션과 실행에 필요한 환경을 이미지로 패키징하여 컨테이너로 실행하고 관리할 수 있도록 지원하는 플랫폼이다.

Docker를 도입하는 대표적인 이유는 다음과 같다.

1. 애플리케이션 개발과 배포가 편리하다.
2. 여러 애플리케이션의 독립성과 확장성을 높일 수 있다.
3. 컨테이너 기술을 쉽게 활용하고 학습할 수 있다.

Docker의 핵심 장점은 단순히 실행 속도가 빠르다는 것이 아니라, **애플리케이션 실행 환경을 표준화하고 재사용할 수 있다는 것**이다.

---

## 2. 1.2.1 애플리케이션의 개발과 배포가 편해집니다

### 2.1 기존 서버 배포 방식의 문제점

Spring Boot 애플리케이션을 Ubuntu 서버에 직접 배포한다고 가정한다.

기존 배포 과정은 다음과 같다.

1. Ubuntu 서버 준비
2. Java 설치
3. 필요한 라이브러리 및 패키지 설정
4. 애플리케이션 파일 배포
5. 환경변수 설정
6. 애플리케이션 실행
7. 정상 작동 여부 확인

이 과정에서 서버별 Java 버전이나 설정이 다르면 오류가 발생할 수 있다.

예시:

| 구분 | 개발 환경 | 운영 환경 |
|---|---|---|
| OS | Ubuntu 24.04 | Ubuntu 22.04 |
| Java | Java 17 | Java 11 |
| 애플리케이션 | Spring Boot | Spring Boot |

개발 환경에서 정상 실행되더라도 운영 환경에서는 Java 버전 차이로 실행에 실패할 수 있다.

이처럼 개발 환경과 운영 환경의 차이는 배포 장애의 원인이 될 수 있다.

### 2.2 Docker를 사용한 배포 방식

Docker에서는 애플리케이션과 실행에 필요한 파일을 이미지로 패키징할 수 있다.

예를 들어 Spring Boot Docker 이미지에는 다음과 같은 항목이 포함될 수 있다.

- Spring Boot 애플리케이션
- Java Runtime
- 애플리케이션 실행에 필요한 라이브러리
- 실행 명령 및 이미지 설정

동일한 이미지를 개발 서버와 운영 서버에서 실행하면 애플리케이션 실행 환경을 일관되게 유지하기 쉬워진다.

### 2.3 Docker 이미지 배포 흐름

```text
개발자가 Spring Boot 개발
           |
           v
Dockerfile 작성
           |
           v
Docker 이미지 빌드
           |
           v
Docker Registry에 업로드
           |
           v
운영 서버에서 이미지 다운로드
           |
           v
Docker 컨테이너 실행
```

### 2.4 주요 구성 요소

| 구성 요소 | 역할 |
|---|---|
| Dockerfile | Docker 이미지 생성 방법 정의 |
| Docker Image | 애플리케이션과 실행 환경을 패키징한 결과물 |
| Docker Registry | Docker 이미지 저장 및 공유 |
| Docker Container | 이미지를 기반으로 생성한 실행 인스턴스 |

### 2.5 Docker 배포의 장점

- 동일한 이미지로 여러 서버에 배포할 수 있다.
- 서버별 실행 환경 차이를 줄일 수 있다.
- 반복적인 애플리케이션 설치 작업을 줄일 수 있다.
- 이미지 버전을 관리할 수 있다.
- 기존 이미지 버전을 활용한 재배포 및 롤백이 편리해진다.

단, Docker 이미지는 호스트 운영체제의 커널이나 서버 네트워크 설정까지 포함하지 않는다.

외부 DB, 환경변수, 방화벽, 스토리지 등은 별도 구성이 필요하다.

### 핵심 정리

**Docker는 애플리케이션 실행 환경을 이미지로 패키징하여 개발과 배포 환경의 일관성을 높이고 배포 작업을 단순화한다.**

---

## 3. 1.2.2 여러 애플리케이션의 독립성과 확장성이 높아집니다

### 3.1 애플리케이션 독립성

하나의 Ubuntu 서버에 다음 서비스를 직접 설치한다고 가정한다.

- Nginx
- Spring Boot
- MySQL

여러 애플리케이션을 동일한 운영체제에 설치하면 다음과 같은 문제가 발생할 수 있다.

- 라이브러리 버전 충돌
- 포트 충돌
- 애플리케이션 설정 충돌
- 서비스별 설치 및 제거 과정의 복잡성

Docker에서는 애플리케이션별 컨테이너를 생성하여 실행 환경을 분리할 수 있다.

```text
Ubuntu Server
     |
     v
Docker Engine
     |
     |--- Nginx Container
     |
     |--- Spring Boot Container
     |
     |--- MySQL Container
```

각 컨테이너는 기본적으로 분리된 프로세스 및 네트워크 환경을 사용할 수 있다.

따라서 서비스별 실행 환경과 라이브러리를 독립적으로 관리하기 쉬워진다.

단, 컨테이너의 실행 환경이 분리되어 있어도 애플리케이션 간 의존성은 존재할 수 있다.

예를 들어 MySQL 컨테이너에 장애가 발생하면 해당 DB를 사용하는 Spring Boot 애플리케이션도 영향을 받을 수 있다.

### 3.2 애플리케이션 확장성

확장성(Scalability)은 서비스의 부하 증가에 대응하여 처리 능력을 늘릴 수 있는 특성이다.

대표적인 확장 방식은 다음과 같다.

| 구분 | 설명 |
|---|---|
| Scale-up | 기존 서버의 CPU, 메모리 등 사양 증가 |
| Scale-out | 서버 또는 애플리케이션 인스턴스 수 증가 |

Docker에서는 동일한 이미지를 이용하여 여러 컨테이너를 생성할 수 있다.

예시:

```text
             사용자 요청
                  |
                  v
              Load Balancer
                  |
         +--------+--------+
         |        |        |
         v        v        v
      WAS 1     WAS 2     WAS 3
     Container Container Container
```

Spring Boot 컨테이너 1개에서 3개로 늘려 트래픽을 분산하는 구조이다.

단, 컨테이너를 늘린다고 트래픽이 자동으로 분산되는 것은 아니다.

로드밸런서 등 별도 구성이 필요하다.

### 3.3 Docker와 고가용성의 차이

Docker로 동일한 서버에서 컨테이너를 여러 개 실행하더라도 서버 자체에 장애가 발생하면 모든 컨테이너가 영향을 받을 수 있다.

따라서 다음 개념을 구분해야 한다.

- 컨테이너 확장: 실행 인스턴스 수 증가
- 고가용성(HA): 장애가 발생해도 서비스가 계속 제공되도록 구성

고가용성을 구현하려면 서버 분산, 로드밸런싱, 장애 감지, 복구 등의 구성을 추가로 고려해야 한다.

### 핵심 정리

**Docker는 애플리케이션 실행 환경을 분리하고 동일한 이미지로 여러 컨테이너를 생성할 수 있어 서비스 운영과 수평 확장을 편리하게 한다.**

---

## 4. 1.2.3 도커를 통해 컨테이너 기술을 쉽게 학습할 수 있습니다

### 4.1 Docker 이전의 컨테이너 기술

Docker가 컨테이너 기술을 최초로 만든 것은 아니다.

Linux에는 기존부터 프로세스와 자원을 격리하고 관리하기 위한 기능이 존재했다.

대표적인 기술은 다음과 같다.

| 기술 | 역할 |
|---|---|
| Namespace | 프로세스가 볼 수 있는 시스템 자원 격리 |
| cgroups | CPU, 메모리 등의 자원 사용 관리 및 제한 |
| LXC | Linux 컨테이너 실행 환경 제공 |

Docker는 컨테이너의 이미지 생성, 배포, 실행, 관리 기능을 사용하기 쉽게 제공한다.

### 4.2 Docker 기본 명령어

아래 명령어는 02장에서 직접 실습할 예정이다.

```bash
# Nginx 이미지 다운로드
docker pull nginx

# Nginx 컨테이너 생성 및 실행
docker run -d --name web01 -p 8080:80 nginx

# 실행 중인 컨테이너 확인
docker ps
```

| 명령어 및 옵션 | 설명 |
|---|---|
| docker pull | 이미지 다운로드 |
| docker run | 컨테이너 생성 및 실행 |
| -d | 백그라운드 실행 |
| --name | 컨테이너 이름 지정 |
| -p 8080:80 | 호스트 8080 포트를 컨테이너 80 포트로 연결 |
| docker ps | 실행 중인 컨테이너 확인 |

### 4.3 Docker와 Kubernetes의 관계

Docker는 이미지 빌드와 컨테이너 실행·관리에 사용되는 기술이다.

Kubernetes는 여러 서버에서 컨테이너화된 애플리케이션을 배포하고 확장하며 운영하는 오케스트레이션 플랫폼이다.

| Docker | Kubernetes |
|---|---|
| 이미지 생성 및 관리 | 컨테이너 애플리케이션 배포 관리 |
| 개별 컨테이너 실행 | 여러 노드에 워크로드 배치 |
| 컨테이너 네트워크·볼륨 관리 | 서비스 연결과 스토리지 관리 |
| Dockerfile, Docker Compose | Pod, Deployment, Service 등 |

Kubernetes는 Docker Engine을 필수 컨테이너 런타임으로 사용하지 않는다.

일반적으로 containerd 또는 CRI-O와 같은 CRI 호환 런타임을 이용할 수 있다.

Docker 학습은 이미지, 컨테이너, 네트워크, 스토리지 등의 공통 개념을 이해하는 데 도움이 된다.

### 핵심 정리

**Docker는 컨테이너 기술을 쉽게 활용할 수 있도록 하며, Docker에서 배운 기본 개념은 Kubernetes 학습에도 연결된다.**

## 5. 실무 적용 예시

### 상황

회사에서 Ubuntu 서버 5대에 동일한 Spring Boot 애플리케이션을 배포해야 한다.

### 기존 방식

각 서버에서 다음 작업을 수행한다.

1. Java 설치
2. 라이브러리 및 실행 환경 설정
3. Spring Boot 애플리케이션 배포
4. 환경변수 구성
5. 애플리케이션 실행
6. 서비스 정상 동작 확인

서버별 설정 차이가 발생할 가능성이 있다.

### Docker 방식

1. Spring Boot 애플리케이션 Dockerfile 작성
2. Docker 이미지 빌드
3. Docker Registry에 이미지 업로드
4. 각 서버에서 동일한 이미지 다운로드
5. 필요한 환경변수와 네트워크 설정 적용
6. Docker 컨테이너 실행
7. 서비스 정상 동작 확인

### Docker 도입 효과

- 애플리케이션 실행 환경 표준화
- 반복 설치 작업 감소
- 배포 일관성 향상
- 서버 증설 시 동일 이미지 재사용
- 이미지 버전 관리 용이

### 주의할 점

Docker는 애플리케이션 실행 환경을 패키징하는 기술이지 서버 전체 구성을 자동으로 복제하는 기술은 아니다.

서버의 OS, 네트워크, 방화벽, 스토리지, 비밀정보 등은 별도 관리가 필요하다.

## 6. 면접 예상 질문 및 답변

### Q1. 기업에서 Docker를 사용하는 이유는 무엇인가요?

Docker는 애플리케이션과 실행에 필요한 환경을 이미지로 패키징하여 일관된 실행 환경을 제공할 수 있기 때문입니다.

또한 동일한 이미지로 여러 컨테이너를 실행할 수 있으므로 배포와 확장, 운영 관리가 편리해집니다.

### Q2. Docker를 사용하면 개발 환경과 운영 환경이 완전히 동일해지나요?

완전히 동일해지는 것은 아닙니다.

동일한 이미지로 애플리케이션 실행 파일과 라이브러리 등의 차이를 줄일 수 있지만, 호스트 커널, 네트워크, 환경변수, 외부 서비스 등은 환경에 따라 다를 수 있습니다.

### Q3. Docker를 사용하면 애플리케이션 확장이 쉬워지는 이유는 무엇인가요?

동일한 이미지를 이용하여 여러 컨테이너를 쉽게 생성할 수 있기 때문입니다.

다만 실제 요청을 여러 컨테이너에 분산하려면 로드밸런서 등의 추가 구성이 필요합니다.

### Q4. Docker 컨테이너를 3개 실행하면 고가용성이 보장되나요?

아닙니다.

하나의 서버에서 컨테이너 3개를 실행하면 해당 서버에 장애가 발생했을 때 모든 컨테이너가 영향을 받을 수 있습니다.

고가용성을 위해서는 여러 서버에 분산 배치하고 로드밸런서와 장애 복구 체계 등을 구성해야 합니다.

### Q5. Docker와 Kubernetes의 차이는 무엇인가요?

Docker는 컨테이너 이미지 빌드와 실행·관리에 활용하는 기술이고, Kubernetes는 여러 서버에서 컨테이너 애플리케이션의 배포, 확장, 복구 등을 관리하는 오케스트레이션 플랫폼입니다.

---

## 7. 2교시 핵심 요약

1. Docker는 애플리케이션 실행 환경을 이미지로 패키징할 수 있다.
2. 동일한 이미지를 사용하면 개발·운영 환경의 차이를 줄일 수 있다.
3. Docker를 이용하면 반복적인 애플리케이션 설치 및 배포 작업을 줄일 수 있다.
4. 컨테이너별로 애플리케이션 실행 환경을 분리할 수 있다.
5. 동일한 이미지로 컨테이너를 추가하여 수평 확장하기 쉽다.
6. Docker 자체가 자동 확장이나 고가용성을 보장하는 것은 아니다.
7. Docker는 Namespace, cgroups 등 Linux 컨테이너 기술을 쉽게 활용하도록 지원한다.
8. Docker에서 익히는 컨테이너 개념은 Kubernetes 학습의 기초가 된다.
