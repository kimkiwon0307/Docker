
## 1장 1교시 — Docker 등장 배경과 컨테이너 개념

### 1. Docker란?
- 애플리케이션과 의존성을 이미지로 패키징하고 컨테이너로 실행·배포·관리하는 플랫폼
- 개발·테스트·운영 환경 간 차이를 줄이고 배포 일관성을 높임

### 2. Docker가 필요한 이유
- 서버마다 Java 버전, 라이브러리, 설정 등이 달라 오류가 발생할 수 있음
- 실행 환경을 동일한 이미지로 패키징하여 환경 차이 최소화
- 동일한 이미지를 여러 서버에서 재사용 가능

### 3. Image와 Container

| 구분 | 설명 |
|---|---|
| Image | 실행에 필요한 파일과 설정을 담은 읽기 전용 템플릿 |
| Container | 이미지 기반으로 생성한 격리된 실행 환경 |

- 하나의 이미지로 여러 컨테이너 생성 가능
- Linux 컨테이너는 호스트의 Linux 커널을 공유

### 4. 데이터 영속성
- 컨테이너 쓰기 계층의 데이터는 컨테이너 삭제 시 사라짐
- Volume / Bind Mount를 사용해 데이터를 별도로 유지 가능

### 5. 인프라 실무 활용
- 애플리케이션 이미지 빌드 및 배포
- 컨테이너 실행·관리
- 네트워크·볼륨 구성
- 로그 분석 및 장애 대응

### 6. 확인문제 및 정답

1. **Docker가 등장한 대표적인 이유는?**
   - 실행 환경을 표준화해 환경 차이와 배포 문제를 줄이기 위해서

2. **Docker는 애플리케이션을 개발하는 기술인가?**
   - 아니요. 애플리케이션의 패키징·실행·배포·관리를 지원하는 플랫폼

3. **이미지와 컨테이너의 차이는?**
   - 이미지: 실행 환경의 템플릿
   - 컨테이너: 이미지로 생성한 격리된 실행 환경

4. **하나의 이미지로 여러 컨테이너를 만들 수 있는가?**
   - 가능함. 각 컨테이너는 개별적으로 실행 가능

5. **컨테이너 삭제 시 데이터는 어떻게 되는가?**
   - 컨테이너 쓰기 계층 데이터는 삭제됨
   - Volume 또는 Bind Mount의 데이터는 별도 유지 가능

### 핵심 한 줄

> Docker는 애플리케이션 실행 환경을 이미지로 표준화하고 컨테이너로 격리 실행하여 배포와 운영을 편리하게 만드는 기술이다.
