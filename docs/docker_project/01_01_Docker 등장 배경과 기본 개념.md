
# 1장 1교시 — Docker 등장 배경과 기본 개념

## 1. Docker란?

Docker는 애플리케이션과 실행에 필요한 의존성을 이미지로 패키징하고, 컨테이너로 실행·배포·관리하는 플랫폼이다.

## 2. Docker가 등장한 이유

### ① 실행 환경의 일관성
- 개발·테스트·운영 서버마다 Java 버전, 라이브러리, 설정 등이 다를 수 있다.
- Docker 이미지에 필요한 실행 환경을 포함하여 환경 차이를 줄일 수 있다.

### ② 배포 및 관리 효율성
- 동일한 이미지를 여러 서버에서 재사용할 수 있다.
- 서버마다 애플리케이션 실행 환경을 반복해서 설치하는 작업을 줄일 수 있다.

## 3. Docker Image와 Container

| 구분 | 설명 |
|---|---|
| Docker | 이미지를 빌드하고 컨테이너를 실행·관리하는 플랫폼 |
| Image | 애플리케이션 실행에 필요한 파일과 설정을 담은 읽기 전용 템플릿 |
| Container | 이미지를 기반으로 생성한 격리된 실행 환경 |

- 하나의 이미지로 여러 컨테이너를 생성할 수 있다.
- 컨테이너는 실행 중이거나 중지된 상태일 수 있다.
- Linux 컨테이너는 호스트의 Linux 커널을 공유한다.
- 각 컨테이너는 독립적인 쓰기 계층을 가질 수 있다.

## 4. Docker의 장점과 한계

### 장점
- 실행 환경의 표준화
- 애플리케이션 배포 및 버전 관리 용이
- 프로세스 격리
- 동일한 이미지 재사용
- 컨테이너 생성 및 제거 편리

### 한계
- 호스트 커널과 네트워크 등 모든 환경 차이가 사라지는 것은 아니다.
- Docker만으로 모든 장애가 해결되는 것은 아니다.
- 컨테이너의 쓰기 계층에 저장한 데이터는 컨테이너 삭제 시 사라진다.
- 영구 보관이 필요한 데이터는 Volume 또는 Bind Mount 등을 사용해야 한다.

## 5. 실무 활용 예시

### Java 버전 불일치 해결

상황:
- 개발 서버: Java 17
- 운영 서버: Java 11
- 애플리케이션: Java 17 필요

해결:
1. Java 17 실행 환경을 Docker 이미지에 포함한다.
2. Spring Boot 애플리케이션을 함께 패키징한다.
3. 해당 이미지로 컨테이너를 실행한다.
4. 호스트에 설치된 Java 11과 관계없이 컨테이너 내부의 Java 17을 사용한다.

## 6. 확인문제 핵심 정답

**Q1. Docker를 사용하는 이유는?**

개발·운영 환경 차이를 줄이고 애플리케이션 배포와 관리를 효율적으로 하기 위해서다.

**Q2. Docker와 Container의 차이는?**

Docker는 컨테이너를 실행·관리하는 플랫폼이고, Container는 이미지로 생성한 격리된 실행 환경이다.

**Q3. Image와 Container의 차이는?**

Image는 실행 환경의 읽기 전용 템플릿이고, Container는 이미지를 기반으로 생성한 격리된 환경이다.

**Q4. 컨테이너는 독립된 Linux 커널을 사용하는가?**

아니다. Linux 컨테이너는 호스트의 Linux 커널을 공유한다.

**Q5. 하나의 이미지로 여러 컨테이너를 만들 수 있는가?**

가능하다. 하나의 이미지를 기반으로 여러 컨테이너를 생성할 수 있다.

**Q6. Docker를 사용하면 모든 환경 차이가 사라지는가?**

아니다. 이미지에 포함된 실행 환경은 일관되게 유지할 수 있지만 호스트 커널, 네트워크, 환경변수 등의 차이는 남을 수 있다.

**Q7. Java 11 호스트에서 Java 17 애플리케이션을 실행하려면?**

Java 17 실행 환경과 애플리케이션을 Docker 이미지에 포함시켜 컨테이너로 실행하면 된다.

## 핵심 암기

- Docker = 컨테이너 실행·관리 플랫폼
- Image = 실행 환경의 읽기 전용 템플릿
- Container = 이미지 기반의 격리된 실행 환경
- Kernel = Linux 컨테이너는 호스트 커널 공유
- 도입 목적 = 실행 환경 표준화 + 배포·관리 효율화
