
# 3장 1교시 — Docker 컨테이너 생명주기와 관리 명령어

## 1. 컨테이너 생명주기(Lifecycle)

Docker 컨테이너는 이미지를 기반으로 생성되며, 실행·중지·재시작·삭제 등의 상태 변화를 가진다.

### 상태 변화

Image → Created → Running → Exited → Removed

| 상태 | 설명 |
|---|---|
| Created | 컨테이너 생성, 아직 실행되지 않음 |
| Running | 컨테이너 프로세스 실행 중 |
| Exited | 컨테이너 프로세스 종료 |
| Removed | 컨테이너 삭제 |

### 핵심 명령어

| 명령어 | 역할 |
|---|---|
| docker pull | 이미지 다운로드 |
| docker run | 컨테이너 생성 + 실행 |
| docker create | 컨테이너 생성만 수행 |
| docker start | 기존 컨테이너 실행 |
| docker stop | 컨테이너 중지 |
| docker restart | 기존 컨테이너 재시작 |
| docker rm | 컨테이너 삭제 |
| docker ps | 실행 중인 컨테이너 조회 |
| docker ps -a | 종료된 컨테이너까지 조회 |
| docker exec | 실행 중인 컨테이너 내부에서 명령 실행 |
| docker logs | 컨테이너 로그 확인 |
| docker inspect | 컨테이너 상세 정보 확인 |

**핵심 차이**
- `run` = 생성 + 실행
- `create` = 생성만
- `start` = 이미 생성된 컨테이너 실행

## 2. Nginx 컨테이너 생성 및 실행

### Docker 이미지 다운로드

```bash
sudo docker pull nginx:alpine
sudo docker image ls
```

- `pull`: Registry에서 이미지 다운로드
- `nginx`: 이미지 이름
- `alpine`: Alpine 기반 이미지 태그

### web01 생성 및 실행

```bash
sudo docker run -d \
  --name web01 \
  -p 127.0.0.1:18081:80 \
  nginx:alpine
```

| 옵션 | 설명 |
|---|---|
| run | 컨테이너 생성 및 실행 |
| -d | 백그라운드 실행 |
| --name web01 | 컨테이너 이름 지정 |
| -p | 호스트와 컨테이너 포트 연결 |
| 127.0.0.1 | 호스트 루프백 주소에만 바인딩 |
| 18081 | 호스트 포트 |
| 80 | 컨테이너 내부 Nginx 포트 |
| nginx:alpine | 사용할 이미지 |

### 정상 동작 검증

```bash
sudo docker ps
curl -I http://127.0.0.1:18081
sudo docker port web01
```

정상 결과: `HTTP/1.1 200 OK`

### 포트 매핑 흐름

Ubuntu Host (127.0.0.1:18081)
        ↓
Docker 포트 게시
        ↓
web01 Container (Nginx:80)

※ 127.0.0.1로 바인딩했으므로 기본적으로 VM 외부에 직접 공개되지 않는다.

## 3. docker create와 docker start

### 컨테이너 생성만 수행

```bash
sudo docker create \
  --name web02 \
  -p 127.0.0.1:18082:80 \
  nginx:alpine
```

생성 직후 상태: `Created`

### 기존 컨테이너 시작

```bash
sudo docker start web02
sudo docker ps
```

시작 후 정상 상태: `Running`

### 차이점

- `docker create`: 생성만 수행
- `docker run`: 생성 후 실행
- `docker start`: 기존 컨테이너 실행

---

## 4. 컨테이너 내부 확인

### docker exec

```bash
# Nginx 설정 검사
sudo docker exec web01 nginx -t

# 컨테이너 호스트명 확인
sudo docker exec web01 hostname

# 웹 문서 디렉터리 확인
sudo docker exec web01 ls -l /usr/share/nginx/html

# 컨테이너 내부 셸 실행
sudo docker exec -it web01 sh
```

### 옵션 설명

- `exec`: 실행 중인 컨테이너에서 추가 명령 실행
- `-i`: 표준입력 유지
- `-t`: 가상 터미널 할당
- `sh`: 셸 실행

**주의사항**
- 중지된 컨테이너에서는 일반적으로 `docker exec`를 사용할 수 없다.
- `exit`로 exec 셸에서 나와도 Nginx 주 프로세스가 실행 중이면 컨테이너는 계속 실행된다.
- Alpine 이미지에는 Bash가 없을 수 있으므로 `sh`를 사용한다.

## 5. 컨테이너 로그 및 상태 분석

### 로그 확인

```bash
# 최근 20줄
sudo docker logs --tail 20 web01

# 실시간 로그 확인
sudo docker logs -f --tail 10 web01
```

- `--tail 20`: 최근 20줄 출력
- `-f`: 실시간 로그 추적
- `Ctrl+C`: 로그 추적 종료

`docker logs`는 기본적으로 컨테이너의 표준출력(stdout)과 표준에러(stderr) 로그를 조회한다.

### 상세 상태 확인

```bash
# 현재 상태
sudo docker inspect \
  --format '{{.State.Status}}' web01

# 호스트에서의 컨테이너 프로세스 PID
sudo docker inspect \
  --format '{{.State.Pid}}' web01

# 전체 상세 정보
sudo docker inspect web01
```

`docker inspect`로 상태, PID, 네트워크, 마운트 등의 정보를 확인할 수 있다.

## 6. 컨테이너 중지·시작·재시작·삭제

### 생명주기 관리

```bash
# 중지
sudo docker stop web01

# 다시 시작
sudo docker start web01

# 재시작
sudo docker restart web01

# 전체 컨테이너 확인
sudo docker ps -a
```

### 컨테이너 삭제

```bash
sudo docker stop web02
sudo docker rm web02
```

### 중요한 차이

| 작업 | 결과 |
|---|---|
| stop | 컨테이너 중지, 객체 유지 |
| start | 기존 컨테이너 재실행 |
| restart | 기존 컨테이너 중지 후 시작 |
| rm | 컨테이너 및 쓰기 계층 삭제 |

- 컨테이너 중지와 삭제는 다르다.
- 컨테이너를 삭제해도 원본 이미지가 자동 삭제되지는 않는다.
- Volume에 별도로 저장한 데이터는 일반적인 컨테이너 삭제 시 유지된다.
- 이미지가 업데이트되어도 기존 컨테이너가 자동으로 새 이미지를 사용하지 않는다.

## 7. 장애 대응

### ① 컨테이너 이름 중복

오류: `container name is already in use`

```bash
sudo docker ps -a --filter name=web01
```

원인: 같은 이름의 컨테이너가 이미 존재한다.

해결: 기존 컨테이너를 확인하고 재사용하거나 다른 이름을 지정한다.

### ② 포트 충돌

오류: `port is already allocated`

```bash
sudo ss -lntp | grep ':18081'
sudo docker ps
```

원인: 다른 서비스 또는 컨테이너가 포트를 사용하고 있을 수 있다.

해결: 포트 점유 대상을 확인한 후 충돌을 해결하거나 다른 포트를 사용한다.

### ③ 컨테이너가 실행되지 않음

오류: `Container is not running`

```bash
sudo docker ps -a
sudo docker logs --tail 30 web01
sudo docker inspect \
  --format '{{.State.Status}}' web01
```

원인: 컨테이너 중지, 애플리케이션 오류 등

해결: 상태와 로그로 원인을 확인한 뒤 필요하면 `docker start`로 실행한다.

### 장애 분석 기본 순서

1. `docker ps -a` → 상태 확인
2. `docker logs` → 로그 분석
3. `docker inspect` → 상세 정보 확인
4. 원인 해결 → 필요 시 재시작
5. `curl` → 정상 동작 재검증

## 8. 확인문제 정답

1. 컨테이너 생성 및 바로 실행?
   - `docker run`

2. 컨테이너 생성만 수행?
   - `docker create`

3. `-d` 옵션의 의미?
   - 백그라운드 실행

4. `-p 127.0.0.1:18081:80`에서 18081?
   - Ubuntu 호스트 포트

5. 종료된 컨테이너까지 확인?
   - `docker ps -a`

6. 실행 중인 컨테이너 내부 명령 실행?
   - `docker exec`

7. `docker stop` 후 `docker start`?
   - 기존 컨테이너를 다시 실행

8. `docker rm web02`의 역할?
   - web02 컨테이너 삭제

확인문제 결과: 8문제 전부 정답 (100점)

## 9. 면접 핵심 질문

### Q1. docker run과 docker start의 차이는?

`docker run`은 새로운 컨테이너를 생성하고 실행한다.
`docker start`는 이미 생성된 컨테이너를 다시 실행한다.

### Q2. docker ps와 docker ps -a의 차이는?

`docker ps`는 실행 중인 컨테이너를 조회한다.
`docker ps -a`는 종료된 컨테이너까지 조회한다.

### Q3. docker exec는 언제 사용하나요?

실행 중인 컨테이너 내부에서 명령어를 실행할 때 사용한다.
설정 검사, 프로세스 및 파일 확인 등의 작업에 활용할 수 있다.

### Q4. 컨테이너가 정상 실행되지 않으면?

`docker ps -a`로 상태를 확인하고,
`docker logs`로 오류 로그를 분석한 다음,
`docker inspect`로 상세 상태를 확인하여 원인을 해결한다.

### Q5. 컨테이너 삭제와 이미지 삭제는 다른가요?

다르다. 컨테이너는 이미지를 기반으로 생성된 실행 환경이다.
컨테이너를 삭제해도 원본 이미지가 자동으로 삭제되지는 않는다.

## 10. 핵심 암기

- Image = 컨테이너 생성에 사용하는 원본
- run = 생성 + 실행
- create = 생성만
- start = 기존 컨테이너 실행
- stop = 컨테이너 중지
- restart = 재시작
- rm = 컨테이너 삭제
- exec = 내부 명령 실행
- logs = 로그 조회
- inspect = 상세 정보 조회

> 컨테이너는 이미지를 기반으로 생성되며, 생성·실행·중지·재시작·삭제의 생명주기를 가진다. 운영 중 장애가 발생하면 상태, 로그, 상세 정보를 순서대로 확인하여 원인을 분석한다.
